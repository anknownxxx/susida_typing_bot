# 寿司打 自動タイピングツール

寿司打（https://sushida.net/play.html、WebGL版）のタイピングを自動化するツール。
画面をキャプチャしてOCRでお題を読み取り、認識した文字列をそのままキーボード入力として送信する。

## 開発の経緯

### 1. 最初にスクレイピングを検討 → 断念

最初はDOM構造を見て、お題テキストをスクレイピングで直接取得できないか検討した。
しかし対象がWebGL版（Unity等でビルドされたゲームがcanvasにレンダリングされているタイプ）で、
画面に見えている文字はすべてピクセルとして描画されているだけで、HTML/DOM上にはテキストノードとして
一切存在しないことが判明。ブラウザの検証ツールでソースを見ても、お題の文字列はどこにも見つからなかった。

この時点でDOMスクレイピングは技術的に不可能と判断し、方針転換。

### 2. 画像認識（画面キャプチャ＋OCR）へ方針転換

「見えているものを画面ごとキャプチャして、OCRで文字を読み取る」方式に切り替えた。
無料で完結させたかったため、以下の構成を採用：

- **mss**：画面の指定領域をキャプチャ
- **Tesseract / pytesseract**：キャプチャした画像から文字を認識（OCR）
- **pyautogui**：認識した文字列をキーボード入力として送信

### 3. 差分検知でのつまずき（背景の寿司皿の映り込み）

当初は前回のフレームと今のフレームのピクセルの差分を見て、お題が切り替わったタイミングを検知する
方式を採用していた。しかしこれが安定せず、原因究明にかなり時間がかかった。

最終的に判明した原因：お題が表示されるボックスの背景が半透明になっており、
プレイヤーの手元に大体4枚程度積み重なっていくと寿司皿の画像が、そのボックス背景越しに透けて見えることがあった。
この本題とは関係ない背景の動きまで差分として拾ってしまい、皿の動きに気を取られて肝心の
お題切り替わりを見逃す、という現象が発生。結果として「お題を1問あるいは2問おきに無視する」という
再現性の高いバグに悩まされた。

トリミング範囲の調整（左右・上下の除外範囲を広げる）で軽減は試みたが、根本解決には至らず、
最終的に検知方式そのものを見直すことにした。

### 4. 検知方式の転換（ピクセル差分 → OCR内容比較）

画面が変化したかどうかではなく、一定間隔でOCRを回し続けて、読み取れた文字列が
前回タイプしたものと違うかどうかで判定する方式に変更。これにより、背景の動きなど
本題と無関係なノイズの影響を受けなくなり、上記の一定間隔で無視される問題が解消した。

## 現状の到達点

- 5000円コースでクリア、36300円分達成（ミスタイプ37回）
- 10000円コースでもクリア、84640円分達成（ただしミスタイプが450〜900回程度と多い）
なお検証回数はさほど多くないのでさらにミスタイプが増える可能性もあると考えられる。

## 既知の課題

- **特定の文字（i, ?, !, 、など）でOCRが誤読し、入力が詰まることがある**
  ボックスの縁に残る小さなノイズが、これらの文字と誤認識されて余分な1文字が入力され、
  寿司打側が「打ちすぎ」を受け付けずそこで止まってしまう、という挙動が疑われる。未解決。
- **たまにOCRが完全に空振りし、1問まるごと無反応になることがある**
- **汎用性がない**：座標(`REGION`)やトリミング比率、フォントサイズを前提にしたチューニングを
  寿司打というサイト・画面サイズに合わせて全部手作業で行っているため、他のタイピングゲームは
  もちろん、寿司打であってもブラウザのウィンドウサイズや表示倍率が変わると座標の取り直しが必要になる。
- **開発者自身のPC環境でしか動作確認をしていない**：`REGION`の座標は、この環境（画面解像度・
  ブラウザの表示倍率・ウィンドウサイズ）に合わせて決め打ちしたもの。別のPCでは画面解像度や
  ブラウザのズーム倍率が異なる可能性が高く、そのままでは座標がズレて動作しない可能性が高い。
  別環境で使う場合は`01_find_region.py`・`01b_view_coordinates.py`で座標を取り直す必要がある。

## 今後の課題

- **汎用性のあるモデルの構築**：座標を手動で決め打ちするのではなく、画面内から自動でお題ボックスを
  検出する、あるいは機械学習ベースの文字認識に置き換えるなどして、他のタイピングゲームや
  画面レイアウトの変化にも対応できる仕組みを検討したい。
  またi, ?, !, 、などのタイプを可能にする仕組みを取り入れること。
## ファイル構成

| ファイル | 役割 |
|---|---|
| `01_find_region.py` | 画面全体を1枚キャプチャして保存する（座標確認の準備用） |
| `01b_view_coordinates.py` | 保存した画像をクリックして、お題ボックスの座標(`REGION`)を割り出すツール |
| `02_diff_detect.py` | （初期プロトタイプ、現在は不使用）ピクセル差分でお題の切り替わりを検知するだけの実験用スクリプト |
| `03_ocr_test.py` | 保存済みのキャプチャ画像に対してOCRの精度を確認するテストスクリプト |
| `04_auto_type.py` | **本体。** ブラウザで寿司打を自動的に開き、OCRの内容比較でお題を検知し、自動タイピングする |

## ロジックの概要（`04_auto_type.py`）

```
1. ブラウザで寿司打のページを自動で開く
2. 一定間隔(OCR_POLL_INTERVAL)ごとに、指定した画面領域(REGION)をキャプチャする
3. キャプチャした画像を前処理する
   - 上側を切り捨て（かな/漢字の行を除外し、ローマ字の行だけ残す）
   - 左右を切り捨て（ボックスの縁のノイズを除外）
   - 下側を切り捨て（皿の重なりが透けて見える帯を除外）
   - 3倍に拡大し、白黒二値化（OCR精度向上のため）
4. TesseractでOCRを実行し、a-zとハイフンだけを許可する設定で読み取る
5. スペース区切りのトークンに分解し、1文字だけのノイズトークンを除いて連結する
6. 読み取れた文字列が「空」または「前回タイプしたものと同じ」なら何もしない
7. それ以外なら、新しいお題とみなしてpyautoguiでキー入力を送信する
8. 送信後は、そのキャプチャ画像を削除する（ファイルが溜まらないようにするため）
```

## セットアップ

```bash
pip install -r requirements.txt
```

加えて、Tesseract OCR本体（エンジン）を別途インストールする必要がある
（Windowsなら[UB-Mannheim版インストーラー](https://github.com/UB-Mannheim/tesseract/wiki)推奨）。
インストール後、`04_auto_type.py`内の`pytesseract.pytesseract.tesseract_cmd`を、
実際にインストールされたパスに書き換えること。

## 実行方法

```bash
python 04_auto_type.py
```

実行するとブラウザで寿司打が自動的に開く。カウントダウンの間にコースを選んでスタートしておくこと。
また寿司打のサイトを開き、ウェブサイトを下にスライドしてしまうと、認識範囲がずれるのでタイプされなくなる。
